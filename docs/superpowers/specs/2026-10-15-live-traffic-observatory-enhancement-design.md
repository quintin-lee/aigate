# 全链路实时流量观测与调用链全景大盘 (Live Traffic Observatory) 设计规范

- **状态**: Approved
- **日期**: 2026-10-15
- **模块**: `web/src/views/LiveView.vue`, `src/observe/event_bus.c`, `src/server/transport_civetweb.c`
- **目标**: 将 aigate 的实时流量运维界面 (`LiveView.vue`) 全面升级为**全功能全链路实时流量观测与调用链全景驾驶舱**，包含顶层实时流量与性能态势雷达、上游提供商健康与 SLA 熔断状态芯片条、高精实时请求流水瀑布与多维过滤、熔断自愈/探活/告警分轨流、单请求链路全景抽屉，以及 SSE 长连接与无锁轮询智能双驱自愈机制。

---

## 1. 业务目标与架构背景

### 1.1 业务背景与诉求
aigate 底层拥有高吞吐无锁事件总线 (`event_bus`)，可在毫秒级广播处理请求事件 (`request`)、熔断状态机变更 (`circuit_breaker`)、探活心跳 (`health_probe`) 与预算告警 (`budget_alert`)。
然而现有的 `LiveView.vue` 界面较为初级：
1. 缺乏顶层瞬时 QPS、P90/P99 延迟分位、错误率及 Token 吞吐速率的宏观态势雷达；
2. 缺乏各上游提供商（OpenAI, Anthropic, DeepSeek, Local Cache）的实时连通性、心跳延迟与熔断状态机（CLOSED / DEGRADED / OPEN）的直观呈现；
3. 左侧请求流水列表缺乏状态码、模型、缓存命中的多维即时快筛，缺少慢请求视觉变色与自动滚屏锁定功能；
4. 右侧告警区域仅简单聚合 4xx/5xx，未分轨解析熔断自愈与心跳探活事件；
5. 点击流水缺少详细的链路耗时、Token 计费与 Guardrail 策略判定抽屉。

### 1.2 架构原则
1. **轻量极速与零负担**：纯前端滑动时间窗口统计，不给网关数据面增加任何锁竞争与计算开销；
2. **多事件总线全轨解析**：完整解析并分轨呈现网关底层发布的 `request`, `circuit_breaker`, `health_probe`, `budget_alert`；
3. **SSE + 轮询双驱自愈**：以 `/admin/v1/events` 长连接为主，弱网或断线时平滑激活 `/admin/v1/audit/events` 轮询保底，保障控制台永不空白；
4. **测试契约与代码规范兼容**：保留原有 `togglePause` 与 `clearEvents` 交互函数，保证整体构建与单元测试 100% 保持通过。

## 2. 界面与交互设计规范

### 2.1 顶层实时流量与性能态势雷达大盘 (Traffic Radar Cards)
位于页面顶部标题与操作栏下方，采用 4 栅格响应式卡片组：

| 栅格卡片 | 滑动计算模型 | 视觉样式 | 说明与业务价值 |
| :--- | :--- | :--- | :--- |
| **⚡ 实时网关吞吐 (QPS)** | 最新 5~10 秒内完成请求数 / 时间跨度 | 亮天蓝 `text-sky-400`，`font-mono` | 实时反映网关并发流量洪峰与吞吐水平 |
| **⏱️ P90 / P99 响应延迟** | 滑窗内所有请求 `latency_ms` 的 90% 与 99% 分位数 | 翠绿色 `text-emerald-400` | 洞察长尾请求延迟，及时发现网络或上游抖动 |
| **🚨 异常与阻断率** | 滑窗内 HTTP $\ge 400$（含策略拦截 403 与 5xx 错误）占比 | 玫瑰红 `text-rose-400` | 统计风控拦截与上游故障总占比 |
| **🪙 Token 吞吐速率** | 滑窗内生成的 Token 总数 / 秒 | 浅紫色 `text-purple-400` | 直观展示 LLM 推理内容生成的瞬时处理速率 |

**右上角控制栏**：
- `SSE LIVE STREAMING`：连接正常时显示动态呼吸绿灯；
- `⏸️ 暂停推送 / ▶️ 恢复实时流`：保留 `togglePause` 方法，方便安全员冻结某一时刻排障；
- `🧹 清屏`：保留 `clearEvents` 方法，清空已捕获历史流水。

---

### 2.2 上游提供商实时健康与 SLA 熔断状态芯片条 (Provider Health Strip)
位于雷达大盘下方、流水瀑布上方，展示主要渠道提供商横向卡片：
- **卡片展示内容**：
  - 提供商名称（如 `OpenAI 官方`, `Anthropic Claude`, `DeepSeek R1`, `本地智能缓存`）；
  - 熔断器状态机标识：
    - 🟢 `CLOSED`（正常）：绿灯，显示心跳探活延迟（如 `38ms`）；
    - 🟡 `DEGRADED`（SLA 降级）：橙灯，显示 SLA 劣化比例，提示已平滑降级；
    - 🔴 `OPEN`（熔断开路）：红灯，提示渠道暂时摘除；
    - 🔵 `CACHE`（缓存命中）：蓝灯，显示平均缓存极速返回延迟（如 `1.2ms`）与命中率；
- **联动交互**：
  - 点击任意提供商卡片，左侧流水瀑布自动设置为仅过滤该渠道流量。

---

### 2.3 实时请求瀑布流与多维快筛 (Request Waterfall)
占据左侧 8 栅格宽：
1. **多维筛选工具条**：
   - 状态快筛胶囊：`全部状态` / `2xx 正常` / `4xx/5xx 异常` / `⚡ 仅看缓存`；
   - 模型下拉快筛；
   - 自动滚屏锁定切换：`🔒 锁定最新流动` 与 `解锁停留排查`；
   - 队列容量控制：保持最近 200 条请求记录，先进先出 (FIFO)。
2. **流水条目 (Waterfall Row)**：
   - 状态码徽章（200 绿、403 红带拦截标签、429 橙、5xx 红、200 CACHED 蓝）；
   - 模型与上游路由（如 `gpt-4o ➔ openai`）；
   - 客户端来源 IP 及 Key ID；
   - 耗时 `latency_ms`（分级变色：<300ms 绿色、300~1000ms 橙色、>1000ms 红色）；
   - Token 数与调用成本核算（如 `68 tok · $0.00018`）；
   - 精确时间戳 `HH:mm:ss`；
   - 点击整行触发打开右侧链路诊断抽屉。

---

### 2.4 熔断自愈与安全告警分轨流 (Alerts & Breaker Stream)
占据右侧 4 栅格宽：
- 分轨接收并渲染：
  1. **⚡ 熔断状态机变更 (`circuit_breaker`)**：黄色卡片，展示新旧状态转变与原因；
  2. **⛔ 安全策略阻断**：红色卡片，展示拦截类型（越狱、涉敏、频控）与来源 IP；
  3. **💓 上游心跳探活 (`health_probe`)**：展示探活周期结果与延迟；
  4. **💰 预算超额预警 (`budget_alert`)**：展示配额触顶通知。
- 顶部保留阻断总计计数。

---

### 2.5 单请求全链路诊断抽屉 (Trace Drawer)
点击流水条目时滑出：
- **基础元数据**：时间戳、状态码、模型、提供商、客户端 IP、Key ID；
- **耗时与缓存分解**：端到端延迟、缓存命中状态；
- **Token 计量与计费**：Prompt Tokens、Completion Tokens、精确预估费用；
- **风控与策略判定**：Guardrail 命中规则与处置动作（PASS / MASK / BLOCK）；
- **快捷操作**：一键复制请求 JSON 诊断摘要。

---

### 2.6 SSE 长连接与优雅自愈降级机制
1. 前端组件挂载时调用 `connectSSE()`，订阅 `/admin/v1/events?token=...`；
2. 捕获 `onmessage` 并依据 `data.type` 路由至请求队列或告警分轨；
3. 若 SSE 断开超过 3 秒，自动启动保底轮询定时器（每 2.5 秒调用 `GET /admin/v1/audit/events`），将新事件增量合入，保证弱网或无长连接支持环境下页面依然生动可用；
4. 当 SSE 重新握手成功后，自动关闭保底轮询；
5. 组件销毁 (`onBeforeUnmount`) 时安全关闭连接与定时器，防止内存泄漏。
