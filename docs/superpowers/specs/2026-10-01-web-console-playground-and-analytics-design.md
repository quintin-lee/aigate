# Web 控制台交互调试场 (Playground) 与可视化时延/成本分布看板设计规范

- **状态**: 草案 (Draft / Pending Approval)
- **创建日期**: 2026-10-01
- **责任模块**: `web/admin.html`, `src/core/pipeline_chat.c`, `src/upstream/model_router.c`, `src/server/admin_api.c`
- **目标**: 为 aigate 提供高交互度的模型与通道实时调试面板（Playground），并在控制台中建立多维可视化时延与成本分布看板，极大提升运营运维与研发调优体验。

---

## 1. 背景与诉求 (Context & Goals)

aigate 作为高性能 C17 核心 LLM 网关，后端具备强大的多通道权重分流、动态故障转移、自适应 Hedging（对冲请求）与按 Token 成本核算能力。但在前端控制台 `web/admin.html` 中存在以下痛点：
1. **现有调试场过于简陋**：仅支持单次请求且每轮请求均覆盖历史，缺少多轮连续对话能力；无法手动直选/排查特定的上游通道（Channel）；缺少首字延迟 (TTFT)、生成速率 (Tokens/s)、单次调用折算成本等核心关键遥测数据。
2. **时延数据缺乏直观呈现**：时延指标目前仅在「监控指标」页以 Prometheus 原始纯文本输出，缺乏 P50/P90/P95/P99 阶梯分布图以及各上游供应商通道的横向响应对比。
3. **成本数据只有扁平表格**：成本归属仅有 4 个总计卡片与单行表格，无法一眼看出哪个模型或部门消耗占比最大，缺乏多维环形占比图与时间走势图。

---

## 2. 整体架构与布局 (Architecture & Layout)

经方案评审，采用 **方案 A：嵌入增强型 (Embedded Enhancement)**：
- 无需新增冗余侧边栏菜单，直接深度升级现有的：
  - **⚡ 实时调试场 (`#tab-playground`)**
  - **💰 成本归属 (`#tab-cost`)**
  - **🛠️ 监控指标 (`#tab-metrics`)**
- 严格遵循内嵌式单文件约束：直接复用已有 Tailwind CSS 与 CDN 加载的 `Chart.js`，零新增体积与外部依赖，完全符合 CMake 编译打包嵌入 C 二进制的需求。

## 3. 功能模块详细设计 (Detailed Specifications)

### 3.1 模块一：全能专业级 Playground 调试面板

#### 3.1.1 三栏自适应布局
* **左栏：参数与通道配置器 (`#playConfigCol`)**：
  * **模型选择器**：下拉列出网关所有已启用的活跃模型，支持从「模型列表」中点击「在调试场打开」时自动选中；
  * **通道直选器 (`#playChannelSelect`)**：
    * `自动路由 (智能负载均衡)`（默认）：遵循网关配置的优先级/加权/延迟/对冲策略；
    * `指定通道直连`：动态解析当前选中模型的 `targets` 数组，展示通道名称、端点及配置权重，支持开发排查单通道连通性与表现；
  * **API 密钥设置**：输入测试密钥，提供「一键自动填充活跃 Key」便捷按钮；
  * **系统提示词 (System Prompt)**：多行文本框，支持折叠与清空；
  * **Prompt 模板快速导入**：可直接从已有的「Prompt 模板库」下拉插入提示词与默认参数；
  * **超参数调节器**：
    * Temperature 滑块 (0.0 ~ 2.0，步长 0.1)
    * Top_P 滑块 (0.0 ~ 1.0)
    * Max Tokens 数字输入 (1 ~ 32768)
    * 流式输出 (SSE Stream) 复选开关（默认开启）
    * JSON Mode 强制结构化输出开关 (`response_format: {"type":"json_object"}`)

* **中栏：连续对话交互流 (`#playChatCol`)**：
  * **消息历史**：内部维护 `messages = [{role, content}]` 上下文数组；
  * **用户消息气泡**：右对齐靛蓝色，显示时间戳与文本；
  * **助手消息气泡**：左对齐深色玻璃质感气泡，带头像、命中上游提供商标签，支持流式 SSE 打字机渐进动画效果；
  * **气泡快捷操作**：
    * 📋 复制内容到剪贴板
    * 🔄 重新生成（自动弹出最后一条助手回复并重新发起请求）
  * **底部输入控制栏**：
    * 扩展文本输入框（Enter 发送，Shift+Enter 换行）；
    * 停止生成按钮（在流式过程中显示，可调用 `AbortController.abort()` 立即断开）；
    * 「清空会话」按钮（一键复位多轮历史）。

* **右栏：实时遥测与诊断面板 (`#playTelemetryCol`)**：
  * **核心指标卡片**：
    * **首字时延 (TTFT)**：从请求发起到首个 SSE chunk 到达的毫秒数；
    * **生成速率 (TPS)**：生成阶段的每秒 Token 产出速度 (`completion_tokens / (total_time - ttft)`)；
    * **端到端总耗时 (Latency)**：整体请求完成毫秒数；
    * **折算成本**：基于所选模型计费单价（`price_prompt_1m`, `price_completion_1m`）动态计算的实际美金金额；
  * **路由诊断元数据**：
    * 实际服务提供商（读取响应头 `X-Upstream-Provider`）；
    * 缓存状态（读取响应头 `X-Cache: HIT / MISS` 及 `Age`）；
    * Token 统计（Prompt Tokens, Completion Tokens, Total Tokens）；
  * **原始流事件折叠检查器 (Inspector)**：
    * 展开可实时滚屏查看原始 SSE `data: {...}` 事件帧及响应报头，方便底层协议排查。

### 3.2 模块二：可视化成本分布看板 (Cost Dashboard)

在现有的 `#tab-cost`「成本归属」标签页头部嵌入 2 块由 `Chart.js` 驱动的可视化图表区：

1. **多维消费占比环形图 (`#costDonutChart`)**：
   * **维度切换**：支持「按模型占比」与「按部门/分组占比」一键切换；
   * **中心指标**：环形中心醒目展示当前筛选周期内的总折算成本（如 `$128.45`）；
   * **图例交互**：点击图例可隐藏/显示特定模型，动态刷新占比。
2. **成本与用量走势复合图 (`#costTrendChart`)**：
   * **双轴/复合展示**：
     * 左轴（柱状）：每日折算成本金额 (USD)；
     * 右轴（折线）：每日消耗的总 Token 数量；
   * **时间跨度联动**：与现有的快速日期预设（今天 / 近7天 / 近30天 / 本月）和自定义日期选择器完全双向联动。

### 3.3 模块三：可视化时延分布看板 (Latency Analytics)

在现有的 `#tab-metrics`「监控指标」标签页头部增加图表区：

1. **时延百分位阶梯柱状图 (`#latencyPercentilesChart`)**：
   * 直观展示当前系统的 **P50 / P90 / P95 / P99** 核心分位时延（ms）；
   * 数据来源：解析 Prometheus HDR Histogram 指标 `aigate_upstream_latency_ns_ns_bucket` 与 `/admin/v1/usage/requests` 最近滑动窗口；
   * 状态着色：根据阈值展示舒适区（绿色 <200ms）、关注区（黄色 200~800ms）、预警区（红色 >800ms）。
2. **上游通道时延横向对比图 (`#providerLatencyChart`)**：
   * 横向条形图，对比所有已配置上游提供商的平均延迟与探活健康延迟（ms）；
   * 帮助管理员快速识别是否存在某个上游通道严重拖慢整个系统尾部延迟。

## 4. 后端 C 网关协同接口规范 (Backend C API Contracts)

### 4.1 通道直连支持 (Direct Upstream Channel Routing)
为支持 Playground 调试特定物理通道：
* **请求头支持**：在 `POST /v1/chat/completions` 中支持可选请求头：
  `X-Aigate-Target-Provider: <provider_name>`
* **网关处理**（在 `src/upstream/model_router.c` 的 `model_router_select_candidates` 中）：
  * 若请求头包含 `X-Aigate-Target-Provider`：在候选通道列表中将该提供商置于首位（或仅筛选出该通道），跳过常规算法选择；
  * 若未包含或通道不存在：回退至模型默认配置的路由策略（加权轮询/故障转移/P95延迟优先）。

### 4.2 诊断响应头确认
网关在响应流中确保输出以下诊断报头（部分已存在，补齐测试）：
* `X-Upstream-Provider: <provider>`（已存在，表明实际处理的上游）
* `X-Cache: HIT | MISS`（已存在）
* `X-Aigate-Latency-Ms: <latency>`（非流式或流式首包输出端到端响应耗时）
